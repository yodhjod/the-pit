# The Pit

A mobile web game made for a group of friends. The player descends a giant pit that opened in the middle of their city, in the spirit of Made in Abyss. The friends appear in the game as characters, but none of them is the main player.

## Direction from the group

- Must run on both Android and iPhone in the browser, with no install. Touch first, keyboard as a fallback.
- Genres voted: adventure/RPG (Pokémon Black/White, X/Y era), hack 'n' slash, survival.
- Tone: sarcastic and parodic on the surface, genuinely dark underneath. The rim town is a tourist trap and the bureaucracy is absurd (delver permits, "NO REFUNDS" signs).
- The city is **Cagliari**, Sardinia (see "Cagliari reskin" below). Not decided yet: the friends' names and looks.

## Game structure (planned)

A rhythm roguelike. The run is a descent through **chapters**, and each chapter is a run of **levels**.

- **Pace:** quick, addictive runs like most roguelikes. Dying ends the run and you start again from the top. Upgrades bought during a run last only for that run. (The Pokémon-style adventure/RPG direction from the group vote is set aside for now.)
- **Fixed levels, structured story:** the levels, their charts and their order are the same every run. The story is told in fixed snippets of lore along the way. The pull is curiosity: see what comes after the level where you last died, and find out what's at the bottom of the pit.
- **Mastery through death:** each death teaches the player the charts, so they get better and faster with practice, like learning a song.

- **Chapters** are each themed on something from the city. The levels in a chapter share that theme. The theme is mostly an art problem, so keep it generic in code for now.
- **Descent levels** are the core gameplay (what `index.html` prototypes). Each one is harder than the last, with its own music, so difficulty rises the deeper you go.
- **Vendor levels:** one or two per chapter. No descending: a calm area with a vendor who sells fun upgrades, and maybe lore or story, before you go on.
  - Stock varies per run (the levels don't), so runs differ in the build you put together.
  - Upgrades come in tiers. Stronger ones appear deeper and cost more. An expensive item may be on display early, out of reach by design, to tease what's coming.
  - Later, different vendor types take different currencies, in the spirit of The Binding of Isaac (shops for coins, devil deals paid in health). For example, a shady vendor deeper down who takes lanterns.
- **Boss level:** the last level of each chapter. You beat it to keep descending. Still rhythm-based, but not about walking down stairs. The gameplay is undecided.
- **Currency:** coins or points earned by playing well, spent at vendors on upgrades.

## Current focus: `index.html` (Pit Descent)

A small gameplay prototype of one chapter, in side view. The real game will be quite different; this file is for finding the feel of the core rhythm loop and the run structure.

- **The run** (`RUN`): Bastione → Via Roma → vendor → Tuvixeddu → Rotatorie → vendor → Sant'Elia (→ boss). **Bosses and minibosses are switched off until they're reworked:** the boss node is commented out of `RUN`, `levelEnd` goes straight to `levelClear` (the `startMini()` call is commented there), and clearing the last node shows "Finish the chapter", then `finish` (Chapter 1 complete). Their code below is kept as it was; `?node=7` no longer exists. The Bastione's music file is commented out in `RUN[0]` for now, so it plays the built-in chart. Each descent level plays one song (a music file, or the built-in 32-beat chart played `PROC_LOOPS` = 3 times with procedural music, about a minute), then its miniboss, then a "Level cleared" screen with its fixed lore line. Lanterns and coins carry over between levels; losing all lanterns ends the run. The deepest node reached is saved in localStorage (`pitBest`) and shown on the title and death screens.
- **Coins:** Perfect = 2, Good = 1, plus upgrade bonuses.
- **Vendors** (`openVendor`, `UPG`): each vendor node lists how many items to roll per tier; stock is random per run, items already owned are skipped. Upgrades are flags in `G.up` checked where they apply (`score`, `loseHeart`, `fail`, `relight`), or change the timing windows `W_P`/`W_G`/`W_S` directly.
- **Boss** (`startBoss`, `BOSS_CHART`, `BOSSG`): the Inspector, a giant eye in a cap. The explorer stands still at the bottom camp. Same four actions: tap = strike, hold = charged strike, swipe up/down = dodge its low sweep / high swipe. Before a sweep the iris takes the cue colour and the eye winds up, then lunges on the beat. 40 HP, the 32-beat chart loops 3 times; if it runs out, the run ends. Placeholder for the boss design.
- **Minibosses** (`MINIS`, `MPH`, `miniSong`, `startMini`, `miniPhrase`, `MINIG`): one at the end of each descent level (`levelEnd`; not after your own song; a dare room leads back to its level, whose end has the miniboss), before the "Level cleared" screen. A call-and-response fight in the spirit of Melatonin. Each phrase is three bars: the **call** (the miniboss flies to the middle of the screen and strikes a faint ghost of the explorer, `GHOST`, on the phrase's rhythm; the ghost dodges each strike the way the explorer will, and each strike has its growl from `miniCue`), an **empty bar** (it flies back in front of the explorer) and the **answer** (it strikes the explorer on the same rhythm, starting on the first beat after the empty bar). In the breather, call and empty bar the built-in music plays drums and bass only (`sg.thin` → `THIN` in `musicBeat0`); the answer gets the full music. A label names the phase: Listen, Ready 3 2 1, Go (`sg.phr`, `#phase`). The answer's growl is as loud as the call's. Inputs are only tap and hold. The game picks how the explorer dodges each tap (`n.kind`, fixed per run, `dodge()`: low sweep → jump, high swipe → duck, slam from the left/right → hop aside); a hold is a beam they brace against. A phrase answered with no mistake costs it 1 HP (3–5 by depth); at 0 it falls into the pit (+5 coins). Phrases come from `MPH` (easiest first): denser through the fight, harder deeper down. A cycle is `MINI_PH` (5) phrases after a one-bar breather (64 beats), each cycle faster (`RAMP`); after `MINI_CYC` (3) it wins. Call notes are cues (`sg.cues`, scheduled like music, not judged); the rhythm track shows an answer only once its call has begun (`n.callT`). Each miniboss has its own theme: `MUSIC[7+L]` at `BPMS[7+L]`. One model recoloured per layer for now. Dev: `__pit.startMini()` starts the fight from wherever the explorer is.

- **The world keeps the beat.** The explorer walks the ledge on their own at a steady pace (`SPEED` units per second); walking is not judged. Their position is a pure function of level time (see the hero section in `frame()`), so the visuals stay on the beat even when the player misses. The walk cycle is locked to the song's beats (a footfall per beat, every other beat above ~140 bpm).
- **The notes are things on the ledge.** A note at level time t sits at distance `SPEED·t` along the ledge, so the explorer reaches it on its beat. tap = whack a critter, swipe up = jump an obstacle or a missing step (`n.gap`), swipe down = duck a swooper, hold = ride a zipline over a chasm (let go on the landing; a swipe or arrow can grab the line too, but the finger or key that grabbed it, kept in `G.holdPtr` by `holdStart`, must stay down), swipe right (forward, `FWD`) = kick a plank barricade off the ledge, swipe left (`BACK`) = brace for a rock that falls onto the explorer on the beat (its shadow grows first), a gaggio lanciatore throws an Ichnusa bottle from 2 beats ahead (chart type `l`: `procSong` turns it into a duck note with `thr` and, 2 beats later, a tap note with `lanc` standing at his spot; linked by `n.fol`/`n.thrN`): the bottle (`n.bot`) leaves his hand `THROWF` beats before the beat and reaches the explorer's head on it; swipe down to duck it (then you still whack him when you reach him), or tap to bat it back (`batBack`: it flies back in `BATBACK` s, knocks him out and his note counts as done; notes judged out of order are stepped over before the miss check). Two-finger tap = shove a SOUVENIRS cart over the edge (the second finger or key must land within `BOTHW` = 120 ms of the first; `onPress(t,id)` tells fingers apart by pointerId, keys by code). Input only changes the outcome: a whack or a bite, a jump or a bonk/fall, a duck or a bat hit, riding the line or dropping in, boards flying or a bonk, a bounce or a rock to the head, the cart rolling off or holding. Swipe directions per move are in `SWT`; `swipeDir` lets the axis the next move expects win diagonal swipes. Keyboard: ←/→ or A/D, and any two keys at once for the cart.
- **The ledge is part of the game** (chart moves `J`, `L`, parsed in `procSong`): `[beat,'J',beats,rise,deadly]` a jump over a gap to a platform `rise` higher or lower; `[beat,'L',rungs,rise]` a ladder, one swipe up per rung (`n.climb`, the explorer hangs and climbs, a missed rung slips). Both become height events on the path (`P.ev`: `pathPt` adds each event's rise over [s0,s1], and a ladder (`lad`) also stops forward travel), so notes and the explorer stay on the beat. Falls: a missed jump costs a lantern, but a deadly one (a `J` of 2+ beats over the open pit, or marked deadly) ends the run on the spot (`deathFall`: the explorer drops out of sight, then `fallOut`). Judged forks with a wrong way were tried and dropped (confusing); forks now only lead to dares (below). Keep a level's rises roughly balanced so the path doesn't climb into the turn above.
- **Free moves** (`freeAct`, `REC`): input outside a note's window still makes the explorer whack, jump, duck, kick, brace or shove (two presses within `BOTHW`), with no judgement. But a whiffed move leaves them off balance for its length (`REC`, also the animation length): until `G.lock`, every input is swallowed ("Off balance"), so jumping too early means the obstacle arrives while you're still in the air and the note is missed. Free moves can't start while riding a zipline or mid-way through a judged jump (`G.busy`). A touch waits to see whether it's a swipe unless a tap, hold or two-thumb note is under 0.6 s away, so swipes work anywhere.
- **Flourish** (`flourish`, Runner 2's dance): a free move within `W_G` of a beat, with no note due within a beat, gives 1 coin and a note in the music, once per beat. Descent levels only. The risk is the off-balance time.
- **The music grows** (`GROW`, `growHit`, `growMiss`, `growApply`), in the spirit of Runner's mode-ups: tiers 0–3. Every `GROW.up` (8) hits in a row add a tier; every mistake (`glitch`) drops one. Each level starts at `GROW.start` (1). Rises land on the next bar; drops land straight away. Built-in music: tier 0 is pad, kick and hats; 1 adds bass and shaker; 2 the arpeggio; 3 a lead. A music file with stems (RUN node `stems:[{src,lv}]`, meant for Suno stems, each aligned with the track) fades each stem in once the tier reaches its `lv`. Without stems, a low-pass opens per tier (`GROW.cut`).
- **The ledge** (`buildLevel`, `pathPt`) is built for each level from its chart and winds down the pit, more than one turn for long songs (at least `MINPITCH` drop per turn so turns never touch). Each layer has its own ledge look in `LSTYLE`: stairs (flat landings and short flights), steel road plates (`plates`), stone slabs, asphalt with a dashed line and a red-white kerb (`road`); Sant'Elia's slabs get sodium street lamps. No handrails on the ledge: they hid the critters. Big one-off wall props (buses, roundabouts, stands, floodlights) are groups flagged `userData.cutG`: `clearLedge` hides them whole when the walkway runs through them (`CUTG`, `onWalk`). Decor is built once at load, so `clearLedge` hides decor instances that poke into the current walkway, and a camera cutaway (`CUT`) dithers away decor right in front of the camera.
- **Layers:** Bastione, Via Roma, Tuvixeddu, Rotatorie, Sant'Elia. Each has its own palette, decor, obstacle, critter colour, ledge look, move mix for generated charts (`LSTYLE[L].mix`, `gap`), and built-in music mode and BPM (98, 108, 116, 124, 132). The boss's built-in music runs at 140, the dare room's at 144. Walk speed follows the tempo: `SPEED` = `PACE` (2.1 units per beat) × bpm/60, set per level in `startLevel`, kept within 3–6.
- **Stakes:** 5 lanterns (hearts). One is relit per new level. After a lantern is lost there's a grace period (`G.grace`, `GRACE` = 3 beats, at least `GRACE_MIN` = 1.4 s; the explorer blinks): further misses cost nothing and don't warp the music again, and whiffs don't knock the explorer off balance. Without it one miss in a dense stretch snowballs, because the warp moves the next notes later than the Good window. Each lantern lost darkens the vignette (`--dmg`) and muffles the music through a low-pass on each music bus (`DMGCUT`, set in `heartsUI`).
- **Speed-up per loop** (`RAMP`): each loop of a built-in chart (the boss's too) plays faster than the last (×1, ×1.06, ×1.12), so beats aren't evenly spaced: use `sg.beats` or `spbNow(t)`/`sg.spbAt(t)`, not `sg.spb`, for the current beat length. `BSP` passes the current beat length to `musicBeat0`.
- **Fever:** at the top music tier (descent levels), coins ×2, a gold pulsing edge (`body.fever`), the camera zooms in a little, and the explorer gets gold sparks that trail behind the walk plus an aura pulsing on the beat (`fevFx`, `FEVP`, `AURA`). Ends with the tier, on any mistake.
- **Chains** (`G.chain`): notes a beat or less apart (from the end of a hold), all hit. From the third on, +1 coin each, shown as "chain ×N".
- **Dares** (`sg.dares`, `dareTry`, `startDare`): on built-in levels, from the second loop on, mid-loop, the ledge forks: a side ledge `DRISE` above the path runs past a dark doorway in the wall (`dareDoor`: a black box sunk into the rock, brought out in front of any house front or sign it overlaps (`WFR`, every flat spot on the wall), a stone frame, a red glow, the DARE? sign above). Beats g-4 to g are empty (g = the gate, beat 16 of the loop). A swipe up on the fork's beat (`f0`, `branchTry`, no judgement) climbs onto the side ledge (`x.br`); doing nothing keeps the explorer on the path. On the side ledge, a free move at the door (window [`a`,`b`)) leaves the level; walking on, the explorer drops back onto the path, landing at `j1` (`brOff` gives the height above the path). Entering leaves the level, which waits (`G.back`): the level stops (`G.state` 'enter', `enterDare`, timings in `ENTER`), the explorer walks to the doorway and into the dark, darkening, an iris closes on them (`irisFx`, `#iris`) and opens again on the dare room: a short, hard mini-level from where the explorer stands, with its own song (`DARE_CHART` played twice, music `MUSIC[6]` at `BPMS[6]`), a red edge (`body.dare`) and no lantern relit. Its RUN node is a copy of the current one with `dare:true`. When it ends (`dareExit`, `G.state` 'exit') the iris shuts, the main level's ledge is rebuilt as it was (`dareBack`: notes before the door count as done), the iris opens on the doorway and the explorer walks out of the dark. The level resumes from the door (`resumePlay`): level time restarts 4 beats before the door's time so the music comes back while the explorer waits there (`G.resumeLt`), then they walk on. Coins from both add up on the level's clear screen. The prize is not decided yet.
- **Mistakes bend and slow the music** (`glitch`, `warp`): for half a second the music is muffled and crunched (both music files and procedural music go through a bus, `mkBus`, with a dry path and a distorted, filtered wet path). The song and the level also slow down together: each mistake adds a warp where level time runs at 1 − depth·sin²(πu), and a music file's playback rate follows the same curve, so they stay in sync (measured within ~3 ms). Wrong key: a music file gets clean copies of itself a semitone up and down (`GL.pitch`) laid over the crunch for the same half second, starting from where the song is and following the slowdown; the built-in music bends every note playing (tracked in `LIVE`) by `pitch[0]` semitones. Each mistake puts the level `slow·slowDur/2` s behind; stacked warps never go below quarter speed. All the knobs are in `GL`. Triggered next to `thud()` on every miss.
- **Feedback:** the rhythm track at the bottom is the main timing UI, with an early/late meter. There's also a ring under the finger, a fixed marker on the ledge where the next move happens, and a flash when its beat hits.
- **Skip intro** (`#skipB`, `skipIntro`): on a music-file level, while the first note is more than ~2 s past the skip point, a button next to Pause jumps level time to 4 beats (at least 2 s) before the first note: it moves `anchorT` and restarts the track at that offset (`trackPlay(sg,when,at)`).
- **Pause** (`pauseGame`, `resumeGame`): the button top left, Escape or P, or the tab going hidden. It suspends the AudioContext, so level time, music and judging all stop (`CK.hold` freezes `clock()`); Resume counts in 3-2-1 first. The Master / Music / Effects sliders (one element, `#pzV`, moved into whichever of the pause menu or the title's Settings screen `#set` is open; Settings also holds the audio delay and Calibrate) set `VOL`, saved as `pitVol`, on gains `VG.out` (after the compressor), `VG.mu`/`VG.muT` (both music buses) and `VG.fx` (the default `OUT` for move sounds). Dragging a slider previews it through its own small AudioContext (`PV`, `pvMusic`, `pvTap`), so it works while the game's is suspended: Music plays the paused song from where you stopped (or the layer's chord) and fades out on release; Master and Effects play the tap sound.
- **Explorer:** a rigged pixel-art sprite generated in code (`drawPose` and `POSES`). Its walk is a cartoon sneak (modelled on a classic sneak-cycle reference): hunched forward and low on tiptoe, arms swinging low and opposite to the legs like a march, hands dangling, swapping with each step (`armSwap`); the far leg and arm are drawn much darker so the alternation reads at small size. The knee lifts high before the beat, then a long toe-first stride lands on the beat. Poses are skeleton coordinates, so friends can be built later by swapping hat, hair, glasses and colours.

**Painted enemies (in progress):** the group wants an ugly, crude early-90s adult-cartoon look (Beavis and Butt-Head inspired) with recognisable Cagliari details, generated in Gemini. Workflow: in one Gemini chat, generate the character on a plain green background, then ask for a 4-frame idle sprite sheet of the same character; save it in `downloads/` (git-ignored); `python tools/cutsheet.py <sheet> art/enemies/<name>` keys out the green, splits the figures and aligns them on the feet. If neighbouring figures touch (they merge into one wide frame), add `--n 4` (`cutsheet.py --n 4 <sheet> <prefix>`): figures are then split by connected blobs. `ART` in `index.html` lists which `FOEVAR` variant uses which frames and its height (`h`, world units; the explorer is 2.35, painted critters are ~3 so details read); critters stand on the pit-side edge of the walkway (`FOE_R`), not on the explorer's line; frames 0/1 swap on the beat (head down for the first 40% of each beat), and the drawn sprite stays until the images load. A third image, `hit` (the critter knocked back towards the right, away from the explorer, with loose bits flying), is cut with `cutsheet.py --one <image> <file> <scale>`; match its scale to the idle frames by eye, since Gemini frames each image differently (the gaggio's idle is 0.27, its hit 0.22). Add `--parts` (`cutsheet.py --one --parts`) to split the loose bits (cap, phone, bottle) off the body into their own images plus a `<hit>.json`; any blob of 40+ px becomes a bit, so check the list it prints and delete stray specks (smoke, motion lines) by hand from the folder and the json; the game throws them forwards with gravity and spin (`n.bits`), so their direction comes from code, not the drawing. On a whack the critter shows its hit pose, holds 0.1 s, then tumbles off with a slow clockwise spin. A fourth image, `atk` (attacking towards the left: punch, throw, bite), is cut with `--one` at the idle scale; `ART` gives it `acx`, where the feet are across the image (0–1), so the feet stay put and the blow reaches out. A missed critter shows it while lunging at the explorer (`n.j==='m'`); if the attack was cut with `--parts` (`ART` `ap:1`), its loose parts are thrown back along the ledge at the explorer, spinning. An optional fifth image, `wind` (`wcx` for its feet), is held from one beat before the critter's note, so a whack on the beat cuts the wind-up short. All poses load through `pose()` in the `ART` loader. Throwing is for specialised thrower characters that attack from a distance (the gaggio lanciatore); the others punch, kick or bite. `FOES` (also on `__pit`) holds every critter variant by key, including ones not placed in `FOEVAR`. Gemini 3.1 Pro (model picker) keeps the character most consistent. ## Tech

- Single self-contained HTML file. No build step.
- Three.js r128 from cdnjs (UMD global `THREE`). Google Fonts: Cormorant Garamond and IBM Plex Mono.
- All art is procedural: low-poly toon-shaded geometry, instanced decor, canvas textures, pixel sprites drawn into canvases.
- Music: a level's music file plays straight to the speakers (`trackPlay`); otherwise procedural Web Audio (a pad, bass, arpeggio and kick per layer, generated per beat in `musicBeat`). The shared echo (`dly`) repeats every half beat: at 3/4 of a beat its repeats fell off the grid and the arpeggio sounded out of sync when the music grew. Move sounds over a music file are short and unpitched (`sfx`).
- **Songs:** everything a level needs is a song object in level seconds (0 = level start): `beats`, `bar0`, `notes` (`at`, `type`, `len`, `gap`), `first`, `end`, plus `buf`/`from` for a music file or `proc`/`lead` for a built-in one. `procSong` builds one from a beat chart; `trackSong` from a generated chart.
- **Music files → levels:** `RUN` descent nodes take `track:'music/x.mp3'` (served over http, so not from `file://`), optional `from`/`to` seconds, and `diff` 0–1. On a load failure the built-in chart plays. Optional `stems:[{src,lv}]`: the track is still analysed and charted from the full mix, but the stems play in its place (see the music grows); if a stem fails to load, the mix plays. The title screen's "Play your own song" analyses any file the player picks and builds one level (difficulty, whole song or best minute, which layer).
  - `analyse` (in-browser, ~0.3 s per 40 s of audio): spectral flux onsets in three bands (lows/kicks, mids/snares and voices, highs/hats), tempo by autocorrelation with a 120 bpm prior, then checked against its non-octave relatives (×3/2, ×2/3, ×4/3, ×3/4) by fitting each as a steady grid over the whole song (a dotted 3+3+2 figure otherwise reads as 4/3 of the tempo), beats by dynamic programming (Ellis 2007), then snapped to a fitted steady grid when the song keeps strict time: the beat chain fits a line, or most 12 s stretches agree with the whole-song grid (syncopation can pull the chain off the beat). Period and phase are fine-tuned against the onset curve. `__pit.sync(url)` reports how a music file's grid and generated chart sit against its onsets. Also finds the bar phase (heaviest kicks) and a per-beat loudness 0–1. On synthetic drum tracks (92–174 bpm, jittered, silent intro) it gets the tempo exact and beats within ~2 ms; `AN.lat` holds the measured frame-time offset.
  - `makeChart`: candidate slots on beats and half-beats (quarters at the top difficulty), a slot gets a note when the music has an accent there, picked two bars at a time with a note budget from difficulty × loudness, with a minimum gap. The band behind each accent picks the move (kicks → jumps, snares → critters, hats → swoopers), nudged towards the layer's mix. Then playability rules (room around swipes, no more than three identical swipes in a row), long quiet stretches become ziplines, then, where the layer's mix has `kick`/`brace`/`both`, some critters become barricades, some swoopers rockfalls and the strongest accents carts. Some jumps become missing steps. For now only the Bastione has the new moves. Deterministic: the same file always gives the same level.
- **Timing:**
  - `timeOf(levelSeconds)` maps level time to AudioContext time and `levelAt(T)` back (`anchorT` = level start, minus the lag from any warps). Never use `anchorT` directly. A music file has no scheduled end: the frame loop fades it out near the level's end.
  - `clock()` returns the *heard* time: it compensates output latency and is smoothed against `performance.now()`.
  - Inputs use the event's own `timeStamp` through `clockAt()`.
  - Move sounds play when the input lands, except a zipline's landing: its sound is scheduled on the landing beat (`n.snd`), whenever the player lets go or keeps holding.
  - The audio delay offset (`offsetMs`) is user-set or measured with the Calibrate screen, and saved in localStorage.
- Built-in charts live in `CHART`: per layer, 32 beats of `[beat, type, holdBeats]`, with type `t`/`u`/`d`/`h`/`k` (kick)/`b` (brace)/`w` (both thumbs)/`l` (gaggio lanciatore, takes 2 beats). Via Roma has one per loop, at beat 20. A level can instead have a hand-built full chart in `CHART_FULL[L]` (beats 0–95, same format, split into the 3 loops by `songFor`; keep 44–48 and 76–80 empty for the dare side ledges). The Bastione has one, built from short repeating phrases with the ledge as gameplay: loop 1 platform hops and a ladder, loop 2 gulls, the zipline and a deadly leap over the pit, loop 3 barricade, rock, a short ladder and the cart. The title screen shows its first loop. The boss chart is `BOSS_CHART`, same format. `LV` is the level being played (`{L, song, path, nd}`) and `ACT` its notes being judged.

## Conventions

- Keep the game a single HTML file unless it grows past the point of being workable. Prefer small, surgical edits.
- Test in a headless Chromium (Playwright with `--use-gl=swiftshader`), or in the desktop app's browser pane via the `the-pit` server in `.claude/launch.json` (serves the folder on http://localhost:8123). Software rendering is slow, so judge visuals from screenshots, not timing accuracy. The pane's tools run in an isolated world: to reach the game's debug hook `window.__pit` (analyse, makeChart, playCustom, CU, LV, G, S, C), inject a `<script>` and pass results back through the DOM. Test helpers live there too (section "dev test helpers"): `synth(o)` renders a drum loop with a steady tone, `song(buf,o)` analyses it and starts a custom level, `stems(o)` does the same with the drums and the tone as separate stems (lv 0 and 2), `growHit()`/`growMiss()` move the music tier, `measure(o)` reports clean vs during-mistake loudness and spectrum peaks on a music bus, `seek(t)` jumps the level to level time t (earlier notes count as done; the camera still eases on real time, so let the game run past the intro first), `report(x)` writes a short JSON to `document.body.dataset.test`, `step()` runs one frame by hand (for checking frame-driven state while the pane is hidden; with the game paused `clock()` is frozen, so set timestamps like `G.enter.t0` relative to it), `errs` collects errors. Audio needs one real click in the pane first. When the pane is hidden its frames are throttled, so `?autoplay` misses notes there.
- Dev switches in the URL: `?autoplay` plays every note perfectly, `?node=N` starts the run at `RUN[N]` (7 = boss), `?coins=N` starts with coins. Runs with `autoplay` or `node` don't update the saved best.
- Keep timing logic driven by audio time. Never move gameplay forward based on input arrival.

## Token budget

Everything in the conversation is re-read on every later step, so what goes in early costs the most.

- Read narrow line ranges (`grep -n` first); never dump whole sections of `index.html` into the conversation. Print only the lines a change touches.
- Edit with exact small replacements. Don't re-read a file to confirm an edit that already succeeded.
- Verify with text, not pictures: `read_console_messages`, `get_page_text`, or a small injected script that returns a short JSON summary. Take a screenshot only when the change is visual, at `scale` 0.5 or less, and only one per check.
- Don't retype long test scripts: reuse helpers already on `window.__pit`, and add new reusable ones there instead of pasting big harnesses.
- Skip verification steps that can't prove anything (for example, frame-driven checks while the browser pane is hidden); say what wasn't checked instead.
- Keep replies and wrap-ups short; no recaps of what the user just read.
- Always ask the user before running a sub-agent, and say what it would do and why it's worth it.
